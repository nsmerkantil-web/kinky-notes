# A-notes: упаковка продукта и подключение моделей

Дата исследования: 5 ноября 2026, Asia/Tbilisi.

Последующее решение пользователя: в первой версии оставить только Ollama и LM Studio. Реализация и результаты упаковки описаны в [отчёте проверки](validation/2026-11-05-packaging.md); остальные провайдеры ниже остаются исследованными возможностями и не входят в v1.

Статус: исследование исходного кода, существующего bundle и официальной документации. Описанные новые подключения и release pipeline не реализованы и не проверены end-to-end. Рабочие записи, настройки и запущенное приложение не изменялись.

## Рекомендуемое устройство продукта

Один распространяемый `A-notes.app` для macOS со встроенным движком распознавания речи. Пользователь отдельно выбирает подключение для текстовых задач: Ollama, LM Studio, OpenAI, OpenRouter или собственный совместимый сервер. Наша серверная инфраструктура для такой версии не обязательна.

Распознавание речи и генерация заметок — независимые части. Whisper преобразует аудио в текст; выбранная LLM обрабатывает текст. Если LLM не подключена, запись и транскрипция должны оставаться доступны, а создание итога — ждать подключения. Отправлять аудио облачной LLM для такого сценария не требуется.

Для первого релиза предлагается прямое распространение подписанного и нотарифицированного DMG, Apple Silicon и macOS 15+. Поддержка Intel, Windows, встроенная LLM и магазин приложений — отдельные направления, требующие своих проверок.

## 1. Что уже есть в проекте

Проверено непосредственно в файлах проекта и существующей сборке:

| Часть | Текущее состояние | Что требуется для продукта |
| --- | --- | --- |
| Приложение | SwiftUI executable, macOS 15 в `Package.swift` | Сохранить нативную упаковку |
| ASR | WhisperKit **0.9.4**, закреплённая зависимость Swift Package Manager | Не требовать от пользователя установки Whisper/Python/Homebrew |
| Веса ASR | `WhisperKit(model: chosenModel)`; загрузка разрешена по умолчанию | Явное управление весами и подготовка до первого звонка |
| Каталог ASR | `refreshModels()` обращается к удалённому каталогу | Сохранённый каталог и рабочий выбор без сети |
| LLM | Адрес `127.0.0.1:11434` задан в исходниках | Настраиваемые подключения и адаптеры |
| Список LLM | Ollama `/api/tags` | Каталог для каждого подключения и ручной model ID |
| Итоги и заголовки | Ollama `/api/chat`, `options`, `think` | Независимые от провайдера задачи |
| Имена участников | Отдельный запрос Ollama с `format: json` | Возможности structured output и безопасная необязательная обработка |
| Задания | Сохраняемые этапы/ошибки и очередь, но без снимка подключения | Зафиксировать провайдера и модель для каждого задания |
| Сборка | `swift build` без release-флага | Воспроизводимая release-сборка |
| Подпись | Собственный локальный сертификат `AntonNotes Local Development` | Developer ID, Hardened Runtime, timestamp, notarization |
| Версия bundle | Нет `CFBundleShortVersionString` и `CFBundleVersion` в build script | Версии релизов и миграций |

Измеренная существующая `dist/A-notes.app`: около **8.8 MiB**, executable **arm64**. `otool -L` показывает системные библиотеки и фреймворки, отдельного внешнего Whisper executable в зависимостях нет. Это размер текущей сборки без включённых ASR-весов, а не прогноз размера релиза или гарантия запуска на другом Mac.

Основные места изменения: `Package.swift`, `scripts/build-app.sh`, новый release signing script, `Sources/AntonNotes/main.swift`, `SummaryService.swift`, `SpeakerAttributionService.swift`, `ProcessingJob.swift`. `TranscriptChat.swift` сейчас отображает реплики; это не реализованный LLM-чат.

## 2. Whisper уже внутри; отдельно нужно решить поставку весов

WhisperKit — библиотека, уже подключённая при сборке. Модель — файлы весов Core ML и сопутствующие ресурсы. В закреплённой версии доступны `modelFolder`, `tokenizerFolder`, `download` и `load`.

Есть два полезных варианта поставки:

| Вариант | Пользовательский опыт | Компромисс |
| --- | --- | --- |
| Обычная загрузка | Устанавливает app, мастер один раз скачивает выбранную ASR-модель | Нужна сеть для подготовки; меньше размер дистрибутива |
| Полный офлайн-дистрибутив | App содержит заранее подготовленную ASR-модель и tokenizer | Больше загрузка и обновления, но ASR доступен без начальной сети |

Рекомендация: обычная поставка с понятной одноразовой загрузкой; дополнительно полный офлайн-вариант, если нужен буквально один передаваемый файл, готовый к распознаванию без интернета. Это два способа доставки одного продукта, а не два движка.

В мастере показывать размер выбранного пакета из manifest, свободное место, прогресс, отмену и повтор. Поддержку продолжения загрузки после разрыва нужно проверить или реализовать явно; наличие downloader в зависимости её не доказывает. Каталог весов закреплять по revision и проверять хеши.

Загруженные/изменяемые модели хранить под `Application Support/AntonNotes/Models`, сохранив текущий внутренний каталог данных. Веса, поставленные с приложением, можно читать из `Contents/Resources`; если необходима запись или подготовка ресурсов, копировать их в Application Support. Подписанный app bundle после установки не изменять.

**Скрытая офлайн-зависимость:** в WhisperKit 0.9.4 `loadTokenizer()` отдельно ищет tokenizer в структуре локального Hub cache и при отсутствии/ошибке обращается к Hub. `download: false` для весов само по себе не запрещает этот путь. Значит, офлайн-поставка должна включать полный tokenizer/config в ожидаемой структуре; повреждение локального tokenizer должно выдавать понятную ошибку, а не незаметный сетевой fallback. Тестировать с пустым пользовательским cache и выключенной сетью.

Точные размер пакета, модель по умолчанию и минимальную RAM выбирать по измерениям на RU/EN-корпусе и целевых Mac. Не переносить многогигабайтную большую модель на все компьютеры автоматически. Текущая строка default для LLM `gemma3:27b` также не подходит как универсальный аппаратный пресет без проверки.

WhisperKit опубликован под MIT; карточка `argmaxinc/whisperkit-coreml` помечена MIT, лицензия исходного Whisper также MIT. В дистрибутив включать соответствующие notices и условия конкретных закреплённых артефактов и транзитивных зависимостей. Не распространять произвольные пользовательские LLM вместе с app без отдельной проверки их условий. [WhisperKit](https://github.com/argmaxinc/argmax-oss-swift), [ASR weights](https://huggingface.co/argmaxinc/whisperkit-coreml/blob/main/README.md), [Whisper license](https://github.com/openai/whisper/blob/main/LICENSE).

## 3. Подключения LLM

### Ollama

Оставить нативный адаптер: `/api/tags` для моделей, `/api/chat` для генерации. Он сохранит уже используемые параметры. Для универсального протокола у Ollama есть и OpenAI-совместимый API на `http://localhost:11434/v1`, но совместимость частичная. [Официальная документация](https://docs.ollama.com/api/openai-compatibility).

Мастер проверяет известный локальный адрес с коротким timeout. Если сервер не отвечает — предлагает открыть установленную Ollama или её страницу загрузки. Если моделей нет — предлагает выбрать модель и явно запустить её загрузку. Загрузку через API и её progress нужно реализовать и проверить; это не текущая функция A-notes.

Ollama остаётся самостоятельным приложением пользователя. Не нужны скрытая установка через shell или обязательный терминал. Адрес редактируемый, чтобы использовать другой порт или собственный сервер.

Важно: localhost не доказывает локальность inference. Ollama может маршрутизировать запросы в облако. Метка «Обработка на этом Mac» должна учитывать выбранную модель и режим, а при неизвестном происхождении показывать «Проверить место обработки». [Ollama local/cloud API](https://docs.ollama.com/api/openai-compatibility).

### LM Studio

Прямая интеграция через OpenAI-совместимые `GET /v1/models` и `POST /v1/chat/completions`, типовой адрес `http://localhost:1234/v1`. Смена только URL в текущем Ollama-коде не работает: отличаются payload и разбор ответа. [Документация API](https://lmstudio.ai/docs/developer/openai-compat).

Пользователь запускает API Server в Developer tab. Мастер должен различать: LM Studio не установлена, приложение закрыто, сервер выключен, неверный порт, моделей нет, требуется авторизация, inference не запустился. Если LM Studio требует API token, сохранить его через Keychain. Получение каталога ещё не доказывает, что выбранная модель загрузится в RAM. [Запуск сервера](https://lmstudio.ai/docs/developer/core/server), [авторизация](https://lmstudio.ai/docs/developer/core/authentication).

### Собственный OpenAI-совместимый сервер

Общий профиль: название, base URL, необязательный API key, model ID и расширенные параметры. Поддержать список `/models`, но оставить ручной ввод model ID для серверов, где каталог не реализован или не отражает разрешения аккаунта.

Такой адаптер расширит охват серверов без отдельной кнопки для каждого продукта. Маркировать совместимость как «текстовые задачи через поддерживаемый API», не обещать «любую модель»: embedding-only модели, неподдерживаемые архитектуры, недоступные модели и слишком маленький контекст не подходят для итогов встреч.

### OpenAI

Отдельный адаптер Responses API для собственных ключей пользователя. Для новых текстовых приложений OpenAI рекомендует Responses; простой общий Chat Completions адаптер не должен ограничивать нативное подключение. Доступные модели определяются аккаунтом и тестовым запросом. [Text generation](https://developers.openai.com/api/docs/guides/text).

### OpenRouter

Подходит как способ получить широкий выбор облачных моделей через одно подключение. Запросы выполняются с ключом пользователя и расходуют его средства. У сервиса есть browser authorization с PKCE: можно предложить «Подключить OpenRouter» вместо ручного копирования ключа. Для macOS отдельно проверить принимаемый callback и возврат в приложение; документация описывает общий OAuth-поток. Ключ — в Keychain. Это дополнительный облачный посредник, что нужно отображать в месте обработки. [Quickstart](https://openrouter.ai/docs/quickstart), [OAuth PKCE](https://openrouter.ai/docs/guides/overview/auth/oauth).

### Gemini и Claude

Gemini предоставляет OpenAI-совместимый endpoint, что позволяет начать с общего адаптера. Для полного управления возможностями полезен нативный адаптер. У Claude есть собственный Messages API, для прямой поддержки закладывается отдельный адаптер. Доступ через агрегатор и прямое подключение к провайдеру — разные профили и учётные данные. [Gemini compatibility](https://ai.google.dev/gemini-api/docs/openai), [Claude Messages](https://platform.claude.com/docs/en/api/messages).

## 4. Codex и вход через ChatGPT: три разных сценария

### A. Модель OpenAI через API

Для создания итога достаточно текстового запроса к доступной модели OpenAI. Codex как процесс для этого не обязателен. В UI честно называть это «OpenAI API», с ключом и доступными моделями.

### B. План пользователя ChatGPT через официальный Sign in with ChatGPT

По проверенной документации есть отдельная возможность ChatGPT plan usage для open-source и локально размещённых приложений. Это требует собственной регистрации/авторизации и разрешения пользователя; не означает доступа к его чатам. Для платных или удалённо размещённых приложений документация направляет в партнёрскую программу. Страница запроса client ID сообщает об ограниченном доступе для коммерческих партнёров. Пока формат распространения A-notes не определён, нельзя обещать этот вход всем покупателям. [Overview](https://developers.openai.com/siwc/token-sharing-open-source), [client ID](https://developers.openai.com/siwc/request-client-id).

При допуске используется публичный Responses API с OAuth access token, `store: false`, `stream: true`, актуальным каталогом моделей выбранного аккаунта. Завершение определяется терминальным событием, включая ошибки лимита уже после начала потока. Этот поток имеет ограничения параметров и не предоставляет transcription API; локальный Whisper остаётся независимым. [Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), [preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

Для A-notes это потенциально более простой путь к желаемому «войти своим аккаунтом и выбрать модель», чем встраивание полноценного агента. Сначала проверить применимость программы к предполагаемой лицензии и способу распространения.

### C. Полноценный Codex внутри A-notes

Codex app-server предназначен для глубоких интеграций с авторизацией, историей и событиями. Нативный Swift-клиент может общаться с дочерним процессом через stdio/JSON-RPC; Node.js для самого протокола не требуется. Для простых итогов это дополнительный процесс и существенно больше жизненного цикла, чем прямой API.

Документация отдельно ограничивает использование прежней app-server authentication в коммерческих/hosted сервисах и рекомендует Sign in with ChatGPT. Поэтому наличие установленного Codex и подписки у пользователя не является достаточным основанием для коммерческой интеграции. [Codex app-server, включая Auth endpoints](https://developers.openai.com/codex/app-server/).

Если позже нужны агентные действия над заметками, прототипировать отдельный Codex adapter с ограниченным доступом и собственной сессией. Не читать чужие auth-файлы и не использовать внутренние backend endpoints. Не выдавать агенту весь пользовательский vault ради обычной генерации итога.

## 5. Как облегчить настройку

Предлагаемый первый запуск:

1. **Подготовить запись.** Понятно объяснить разрешения macOS для микрофона и системного звука, показать короткую проверку записи и воспроизведения.
2. **Подготовить распознавание.** Определить установленный ASR-пакет или предложить загрузку; показать место, размер и готовность. Для офлайн-поставки — проверить локальные файлы.
3. **Выбрать обработку текста.** «На этом Mac» → найденные Ollama/LM Studio; «В облаке» → провайдер/авторизация; «Свой сервер» → адрес. Разрешить «Позже».
4. **Выбрать модель.** Получить каталог, отфильтровать явно неподходящие модели, оставить расширенный ручной ввод. Объяснить неизвестные характеристики без выдуманного рейтинга.
5. **Проверить подключение.** Выполнить маленький синтетический запрос. Не отправлять реальную встречу для первоначального теста. Показать успех либо конкретную причину ошибки.
6. **Показать готовность.** Например: «Распознавание: готово · Итоги: LM Studio / выбранная модель · Обработка: на этом Mac», только если это установлено.

Состояния настроек должны быть различимы: сервер доступен; модель найдена; модель отвечает; разрешены текстовые задачи; structured output проверен/неизвестен. Не сводить всё к одному зелёному индикатору после `GET /models`.

При выборе облака явно показывать, что туда отправляются транскрипт и нужные ручные заметки; не переводить незавершённое локальное задание в облако автоматически. Для собственного сервера показывать его адрес и не утверждать, что он офлайн. Ключ привязывать к конкретному подключению; не пересылать его на другой host при redirect или смене URL.

## 6. Архитектура подключения

```text
Микрофон + системный звук
            ↓
     Локальные аудиофайлы
            ↓
   WhisperKit + ASR assets
            ↓
      Полный транскрипт
            ↓
  Задача: итог / заголовок / имена
            ↓
    Общий интерфейс LLM
      ├─ Ollama native
      ├─ OpenAI-compatible → LM Studio / custom / Gemini / OpenRouter
      ├─ OpenAI Responses → API key
      ├─ ChatGPT plan usage → OAuth, если применимо
      └─ Claude Messages (следующий этап)
            ↓
     Проверка результата
            ↓
   Локальное хранилище текстов
```

Предлагаемые сущности, не реализованный код:

- `AIConnection`: UUID, вид провайдера, URL, название, ссылка на credential в Keychain.
- `ModelDescriptor`: model ID и известные возможности; неизвестные значения остаются неизвестными.
- `LLMClient`: проверка подключения, каталог моделей, текстовый запрос, поток событий, отмена, нормализованные ошибки.
- `ModelCapabilities`: контекст, streaming, structured output, reasoning и разрешённые параметры. Каталог не всегда сообщает всё — нужны профиль и минимальные probes.
- `AIJobConfiguration`: connection ID, model ID, версия prompt и параметры, сохранённые в момент постановки задания. Секреты в job не сохраняются.
- `GenerationResult`: текст, статус завершения, usage, причина прерывания, provider/model provenance.
- `ModelAssetManager`: manifest ASR, загрузка, проверка, удаление и импорт локального пакета.

Не передавать Ollama-параметры `num_ctx`, `num_predict`, `think`, `format` в другие API напрямую. Не предполагать, что каждая модель принимает `temperature`, JSON schema или одинаковые роли сообщений. Предусмотреть ответ без structured output: необязательные имена можно пропустить, сохранив успешно созданный итог.

Разбиение длинных транскриптов адаптировать к контексту модели с резервом под prompt и ответ. Текущие лимиты по числу символов — исходная эвристика, не универсальный token budget. Не сокращать исходный транскрипт скрыто. Сохранить конкретные темы, имена, позиции, договорённости и неопределённость, а результат проверять на русском, английском и смешанной речи.

В текущем Store ASR engine кешируется. На Mac с ограниченной unified memory нужно измерить пик ASR + LLM и при необходимости освобождать ASR перед загрузкой LLM. Размер весов сам по себе не описывает общую RAM с KV cache и длинным контекстом.

Переход к другому провайдеру не должен терять аудио, транскрипт, ручные заметки или предыдущую версию итога. Повтор отправки облачного запроса может стоить денег, поэтому нужны ограниченные retries, явный статус и сохранение успешно законченных частей. Сохранять частичные результаты отдельно от окончательного итога.

## 7. Подготовка к передаче приложения

Нынешняя локальная подпись не заменяет Developer ID. Для обычного пользовательского релиза:

1. Release build для выбранной архитектуры и воспроизводимый набор зависимостей.
2. Собрать bundle с версиями, иконкой, notices, разрешениями и необходимыми ресурсами.
3. Проверить отсутствие зависимостей от локального checkout, Homebrew, developer cache и машинных путей.
4. Подписать вложенные исполняемые компоненты и app через Developer ID Application с Hardened Runtime и secure timestamp. Не включать лишние исключения runtime.
5. Отправить дистрибутив на notarization через `notarytool`, проверить результат и журнал, прикрепить ticket через stapler; сформировать проверенный DMG с переносом в Applications.
6. Скачать этот DMG и пройти установку и первый запуск на другом Mac или чистом пользователе. Проверить Gatekeeper и полный рабочий цикл.

Apple описывает эти требования и отдельно рекомендует проверку на другом Mac. Прямой релиз не требует обязательного App Sandbox; Mac App Store требует, поэтому магазин — отдельная проверка захвата, файловых прав и интеграций. [Notarization](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution), [preparing distribution](https://developer.apple.com/documentation/xcode/preparing-your-app-for-distribution), [packaging](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution).

Предусмотреть миграцию существующих пользовательских данных без потери записей. Смена development identity на Developer ID требует отдельной проверки разрешений macOS и доступа к Keychain; не обещать автоматический перенос TCC.

Загрузка пользовательских моделей не должна увеличивать размер каждого обновления приложения. Автообновления можно добавить отдельным этапом; первая бета может обновляться вручную, если сохранность данных и версии уже проверены.

## 8. Последовательность реализации

### Этап A — переносимая основа

Отделить ASR assets от кода, добавить подготовку и офлайн-проверку; сделать release bundle и pipeline подписи. Сохранить существующий Ollama workflow через адаптер. Добавить job snapshot и provenance.

Готовность: приложение на чистом Mac получает/находит ASR, записывает тестовый разговор, создаёт транскрипт, сохраняет его и открывает после перезапуска без developer окружения.

### Этап B — первая версия с выбором модели

LM Studio, общий OpenAI-compatible профиль, OpenAI Responses, мастер, Keychain, каталог и синтетическая проверка inference. OpenRouter сначала можно поддержать ключом через общий адаптер; browser authorization — отдельная проверяемая задача.

Готовность: один и тот же тестовый материал проходит через Ollama и LM Studio; облачные проверки выполняются только с выбранными пользователем credentials и разрешённым материалом. Задание использует зафиксированное подключение даже при изменении настроек.

### Этап C — удобство и расширение

OpenRouter OAuth, прямой Claude/Gemini при необходимости, измеренные аппаратные пресеты, дополнительный offline DMG, обновления. Отдельно определить OSS/бесплатную локальную или платную модель распространения и проверить применимость Sign in with ChatGPT. Полноценный Codex app-server добавлять при конкретной потребности в агентных функциях.

Ни одно подключение нельзя объявлять готовым только потому, что известны его endpoints или компилируется адаптер.

## 9. Минимальная проверка перед внешней бетой

| Проверка | Критерий |
| --- | --- |
| Чистая установка | Запуск из скачанного DMG без Xcode, Python, Homebrew и cache разработчика |
| Gatekeeper | Подпись, notarization и stapled ticket корректны |
| Разрешения | Отказ/выдача доступа, микрофон и системный звук дают понятное состояние |
| ASR онлайн | Видны этапы загрузки/подготовки; разрыв сети и нехватка диска обработаны |
| ASR офлайн | Нет необходимых сетевых обращений с пустым cache и поставленными assets/tokenizer |
| Нет LLM | Запись и транскрипт сохраняются; итог можно создать позже |
| Ollama | Нет сервера, пустой каталог, неверная модель, рабочая модель, локальный/cloud режим |
| LM Studio | Выключенный server, auth, незагруженная модель, нехватка RAM, успешный итог |
| Custom API | Нестандартный URL, нет `/models`, ручной model ID, частичная совместимость |
| Cloud | Неверный ключ, исчерпанный баланс/лимит, timeout, обрыв stream, корректный terminal status |
| Длинный звонок | Полнота итогов без скрытой потери частей; RU/EN; отмена и повтор |
| Сон и перезапуск | Сохранённое задание восстанавливается с прежним провайдером; нет ложного «Готово» |
| Обновление | Аудио, тексты, ручные правки и настройки переживают замену app |

## Решения, которые остаются открытыми

1. Бесплатная локальная/open-source версия или коммерческое приложение: это влияет прежде всего на путь ChatGPT sign-in.
2. Нужен ли полный офлайн-дистрибутив при первом запуске или достаточно загрузки ASR в мастере.
3. Минимальный поддерживаемый Mac и измеренная ASR-модель по умолчанию.
4. Доступ к Developer ID для настоящего внешнего релиза.

Эти решения не мешают спроектировать общий интерфейс провайдеров. Рекомендуемый первый внешний продукт: **A-notes для Apple Silicon/macOS 15+, встроенный WhisperKit, управляемая ASR-модель, Ollama + LM Studio + custom API + OpenAI, локальные данные, подписанный DMG.** OpenRouter упрощает широкий выбор облачных моделей; ChatGPT/Codex требует отдельного подтверждённого способа авторизации для выбранного формата продукта.
