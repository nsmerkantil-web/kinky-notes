# Review: локальное распознавание встреч для A-notes

Дата исследования: 6 ноября 2026. Статус: исследование и предложение для проверки; движок приложения не изменён. Аудиозаписи в сторонние сервисы не отправлялись. Приведённые внешние показатели не являются результатами A-notes.

## Решение

Для текущей версии сохранить **WhisperKit + Whisper large-v3-turbo** как базовый вариант. Первым экспериментом проверить **открытый SpeakerKit** для разделения голосов. Вторым — сравнить **FluidAudio + Parakeet v3 / Ultra** с текущим движком по скорости и качеству RU/EN. Для режима повышенного качества сравнить **Whisper large-v3** с turbo на одинаковом runtime. Qwen3-ASR оставить исследовательским кандидатом.

Это рекомендация по порядку экспериментов, а не доказанный рейтинг точности. Ни документация, ни найденные отзывы не устанавливают победителя на наших русско-английских митингах.

## Наша исходная точка

Проверено непосредственно в проекте и на компьютере:

- MacBook Pro, Apple M4 Pro: 12 CPU-ядер, 16 GPU-ядер, 48 ГБ объединённой памяти. Идентификаторы устройства в документ не включены.
- Swift/macOS-приложение, deployment target macOS 15; WhisperKit закреплён на **0.9.4** в `Package.swift`.
- Встроенная модель — `large-v3_turbo` (`Sources/AntonNotes/BundledASR.swift`).
- `main.swift`, `processMeeting`: отдельные `microphone.caf` и `remote.caf`, последовательная обработка окнами 30 секунд, RMS-фильтр, сохранение прогресса, кэш движка.
- На каждом активном окне вызывается определение языка. Если результат не ru/en, выполняются две попытки ru/en с выбором по среднему `avgLogprob` (`TranscriptionPolicy.swift`). Это эвристика, а не проверка правильности текста; возможны дополнительные затраты и принудительный неверный язык.
- Акустической диаризации сейчас нет. Подписи «Локальный микрофон» и «Удалённая сторона» обозначают источник аудио. `SpeakerAttributionService` ищет осторожные текстовые свидетельства имён через LLM; разные голоса этим не выделяются.
- Каталог проекта сейчас не является Git-репозиторием. Review подготовлен локально для будущего GitHub, без публикации.

48 ГБ дают хороший запас для рассматриваемых компактных ASR-моделей. Это инженерная оценка вместимости, не замер пикового потребления: загрузка Core ML, временные буферы, диаризация и параллельно работающая LLM тоже расходуют память.

## Модель, движок и определение говорящих — разные решения

**Модель** определяет распознавание: например, large-v3-turbo или Parakeet v3. **Runtime** исполняет её: WhisperKit/Core ML, whisper.cpp/Metal, MLX или CTranslate2. Замена runtime при тех же весах прежде всего меняет производительность и интеграцию; квантование, декодирование и разбиение аудио могут также изменить результат.

**Диаризация** отвечает «кто говорил когда», выдавая Speaker 1, Speaker 2 и интервалы. Она оценивает число различимых говоривших, а не число участников звонка: молчавших людей по аудио посчитать нельзя. Имя человека — отдельное пользовательское назначение или подтверждённая атрибуция. Перекрывающаяся речь и короткие реплики могут приводить к объединению и раздвоению голосов.

## Основные кандидаты

| Связка | RU / EN | Сильная сторона для нас | Ограничение | Предлагаемая роль |
|---|---|---|---|---|
| WhisperKit + large-v3-turbo | Обе | Уже интегрирована; нативный Swift | Нет встроенного в сам Whisper определения голосов | Базовая конфигурация |
| WhisperKit + large-v3 | Обе | Кандидат для сравнения качества с turbo | Больше вычислений; превосходство на наших встречах не установлено | Режим качества после тестов |
| FluidAudio + Parakeet TDT 0.6B v3 / Ultra | Обе | Core ML, Swift; перспективная скорость | Нужно проверить длинные встречи, термины и смешанную речь | Главный кандидат на ускорение |
| whisper.cpp + large-v3-turbo / small | Обе, если мультиязычные веса | Metal/Core ML, квантование, переносимость | C/C++-интеграция и собственная упаковка | Переносимый backend |
| Qwen3-ASR 1.7B / 0.6B | Обе | Альтернативное семейство ASR | Нужен отдельный проверенный путь исполнения/упаковки на Mac | Эксперимент |

Whisper предоставляет несколько размеров; turbo — оптимизированный вариант large-v3. Публичная таблица скоростей OpenAI измерена на A100: её коэффициенты нельзя использовать как прогноз для M4 Pro. Англоязычные `.en`-модели не подходят как общий RU/EN-профиль. [OpenAI Whisper](https://github.com/openai/whisper).

В текущем Argmax OSS есть отдельные продукты WhisperKit и SpeakerKit; SpeakerKit работает через Core ML и Pyannote community-1, поддерживает автоматическое число голосов и объединение диаризации с транскрипцией. **Этого нет автоматически в закреплённом у нас WhisperKit 0.9.4**: потребуется отдельная миграция и проверка. [Argmax OSS](https://github.com/argmaxinc/argmax-oss-swift), [релизы](https://github.com/argmaxinc/argmax-oss-swift/releases).

Parakeet **v3** поддерживает русский и английский среди 25 языков; v2 не следует подставлять вместо него для русского. Длинное аудио поддерживается моделью, но опубликованные пределы full/local attention относятся к определённым условиям NVIDIA; Core ML-пайплайн нужно проверять отдельно. [Карточка NVIDIA](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3).

Ultra — post-training v3 с теми же 25 языками. Авторы FluidAudio рекомендуют его для новых интеграций; в их парном тесте FLEURS он улучшает русский на 1,3 процентного пункта WER относительно v3 при близкой скорости. Это результаты авторов конвертации, не независимое доказательство превосходства на встречах. Сохранять v3 как воспроизводимый контроль. [Документация Ultra](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/ASR/ParakeetUltra.md).

whisper.cpp поддерживает Apple Silicon, Metal, Core ML encoder и квантование. Возможность квантовать полезна для небольших машин, но размер файла не равен полной RAM процесса. Для M4 Pro это скорее альтернативный backend и средство независимой проверки, чем очевидная необходимость заменить Swift-движок. [whisper.cpp](https://github.com/ggml-org/whisper.cpp).

Qwen3-ASR поддерживает русский и английский; семейство включает 1.7B/0.6B и отдельный ForcedAligner. Текстовые модели Qwen, уже используемые для заметок, не заменяют ASR-модель. Качество и скорость нативного Mac-пути ещё предстоит установить. [Qwen3-ASR](https://huggingface.co/Qwen/Qwen3-ASR-1.7B).

## Другие варианты и причины не ставить их первыми

- **MLX Whisper**: полезен как Apple Silicon-прототип для сравнения; Python-окружение добавляет работу по распространению относительно существующего Swift-приложения. Сам по себе не решает диаризацию. [MLX example](https://github.com/ml-explore/mlx-examples/blob/main/whisper/README.md).
- **faster-whisper**: хорош для отдельного Python/server-профиля, но «faster» не гарантирует преимущество на Mac. В текущей документации CTranslate2 нет Apple GPU backend; CPU и NVIDIA/AMD GPU перечислены отдельно. [faster-whisper](https://github.com/SYSTRAN/faster-whisper), [поддержка оборудования](https://opennmt.net/CTranslate2/hardware_support.html).
- **WhisperX**: готовая комбинация распознавания, выравнивания слов и pyannote. Полезный лабораторный baseline; Python, alignment-модели и зависимости усложняют поставку нативного приложения. Выравнивание слов не исправляет ошибочно распознанные слова. [WhisperX](https://github.com/m-bain/whisperX).
- **Apple SpeechAnalyzer / SpeechTranscriber**: системный путь для длительной речи, доступный в новом поколении ОС. Нельзя обещать русский по поддержке языка в Dictation или Translate: проверять `supportedLocales` и доступность на устройстве. Для общего macOS 15-профиля это дополнительный backend с проверкой версии ОС. [WWDC](https://developer.apple.com/videos/play/wwdc2025/277/), [API](https://developer.apple.com/documentation/speech/speechtranscriber).
- **VibeVoice-ASR 9B**: объединяет текст, голоса и время; заявлен вход до 60 минут и multilingual/code-switching. Для 90 минут понадобится отдельная стратегия сшивки. Намного тяжелее компактных кандидатов; вместимость весов в 48 ГБ не доказывает приемлемый расход памяти на длинном контексте или скорость на Mac. Пока исследовательский вариант. [Microsoft model card](https://huggingface.co/microsoft/VibeVoice-ASR).

## Как получить «Собеседник 1 / Собеседник 2»

Первый вариант — **WhisperKit + открытый SpeakerKit**. Альтернатива — **FluidAudio offline diarization**, которую можно использовать и при сохранении Whisper для текста. FluidAudio публикует offline community-1-пайплайн и несколько streaming-вариантов; для готовой записи начать с offline. У Sortformer есть ограничение в четыре голоса, поэтому он не универсален для групповых встреч. [FluidAudio](https://github.com/FluidInference/FluidAudio).

Для эталонного сравнения использовать оригинальный **pyannote community-1**: он поддерживает offline-работу после получения весов и exclusive-диаризацию для удобного сопоставления с ASR. Доступ к исходным весам требует принятия условий на Hugging Face; это учесть в onboarding. [Карточка pyannote](https://huggingface.co/pyannote/speaker-diarization-community-1).

Предлагаемая архитектура A-notes:

1. Сохранять микрофон и remote раздельно с единой временной шкалой.
2. Распознавать речь; remote диаризовать по полной встрече или с глобальным согласованием голосов. Микрофон тоже может содержать несколько людей при записи комнаты.
3. Назначать speaker ID словам/коротким фрагментам по временным интервалам. Делить реплику при смене голоса, оставлять unknown/overlap, если уверенности нет.
4. Сохранять стабильные ID внутри встречи; имя назначать отдельно, разрешить ручные merge/split и переименование.
5. Формировать заметки из итогового транскрипта, сохраняя исходный текст и аудио для проверки.

Не кластеризовать каждый 30-секундный блок независимо: Speaker 1 одного блока иначе не обязан совпасть со Speaker 1 следующего. Предусмотреть утечку remote в микрофон при работе через динамики: один человек может появиться на двух дорожках. Дедупликацию и echo cancellation проверять отдельно от ASR; простое удаление совпавшего текста может убрать настоящее повторение.

## Что действительно говорят цифры и отзывы

У FluidAudio есть ASR-тест на **M4 Pro 48 ГБ**: FLEURS English — WER 5,4%, RTFx 207,4; Russian — WER 7,2%, RTFx 209,7. Это короткие читаемые фразы, не шумная встреча. Другие разделы той же страницы уже относятся к M5 Pro: их нельзя приписывать нашему Mac. Для диаризации авторы явно различают протоколы: на AMI IHM получено DER 20,3% при defaults и 18,3% при более дорогих настройках с учётом перекрытий, против опубликованных 17,0% community-1. Красивое число из теста, исключающего overlap, с ними несопоставимо. [Методология и результаты FluidAudio](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/Benchmarks.md).

RTFx = длительность аудио / время обработки; больше — быстрее. Для **одной** дорожки 90 минут при условном RTFx 10 означают 9 минут обработки, при 30 — 3 минуты. Это арифметические примеры, не прогноз. Две полные дорожки увеличивают объём работы, а startup, диаризация и суммаризация добавляют своё время.

В [отзыве разработчика после интеграции Parakeet](https://www.reddit.com/r/LocalLLaMA/comments/1nf10ye/30_days_testing_parakeet_v3_vs_whisper/) отмечены высокая скорость, проблемы с терминами, неравномерное качество языков и сложности overlap/числа голосов. Это личный опыт, без контролируемого RU-бенчмарка; утверждение из старого отзыва об отсутствии словаря не переносить автоматически на нынешний SDK. В [issue faster-whisper](https://github.com/SYSTRAN/faster-whisper/issues/911) описана ошибка `device="mps"`; нынешнюю поддержку проверяли по документации CTranslate2, а не только по старому issue.

Практический вывод: проверять термины, пропуски и назначение голосов, а не выбирать по рекламному «100×» или общей позиции в leaderboard.

## Улучшения пайплайна, которые проверить независимо от модели

Это предложения по результатам чтения нашего кода, пока без реализации:

- Вместо единственного RMS-порога проверить VAD с запасом до/после речи. Не обрезать тихие окончания и короткое «да».
- Сравнить жёсткие границы 30 секунд с разбиением по паузам и небольшим overlap; удалять дубли по времени и словам, не только по строковому совпадению.
- Сохранить абсолютные timestamps и checkpoint. Схема checkpoint должна учитывать движок, ревизию весов, настройки и версию препроцессинга, чтобы не смешивать разные эксперименты.
- Сравнить auto, ru, en и mixed-политику. Определение языка на каждом коротком окне нестабильно; не считать `avgLogprob` двух разных декодирований эталоном правильности.
- Отдельно измерять detect-language, encoder, decoder, VAD, диаризацию и startup. Сначала убрать ненужные повторные вычисления, затем выбирать runtime.
- Не «исправлять» транскрипт LLM без сохранения оригинала: иначе модель может добавить правдоподобный, но не произнесённый термин.

## Профили для будущих пользователей

Предлагаемая стартовая матрица, а не заявленные минимальные системные требования:

| Пользователь | Что предложить | Что необходимо проверить |
|---|---|---|
| Apple Silicon, 8 ГБ | Whisper small multilingual или компактный Parakeet-профиль | Пиковая RAM, swap; ASR и LLM запускать последовательно |
| Apple Silicon, 16 ГБ | turbo или Parakeet | Общая память при диаризации и генерации заметок |
| Apple Silicon, 24–48+ ГБ | turbo как baseline, large-v3 как quality-кандидат, Parakeet как speed-кандидат | Выбор по RU/EN-корпусу, не только объёму RAM |
| Intel Mac | whisper.cpp CPU и небольшая мультиязычная модель | Реальная скорость и поддержка всего приложения; текущую сборку не считать проверенной |
| Windows/Linux, NVIDIA | faster-whisper / WhisperX как отдельное направление | Потребуется портирование приложения, не только смена модели |

В интерфейсе достаточно нескольких осмысленных профилей. Не выдавать список из пяти моделей без объяснения языков, размера загрузки, ограничений и возможностей speaker labels.

## Лицензии и GitHub-поставка

Лицензии кода и весов проверять раздельно. Whisper — MIT; Argmax OSS — MIT, но SpeakerKit Core ML-веса — **CC BY 4.0**. Parakeet v3 также CC BY 4.0. Поэтому «код приложения под MIT» не заменяет атрибуцию моделей. Для Ultra и иных производных отдельно зафиксировать upstream, лицензию и изменения конвертации до включения в релиз. [Whisper](https://github.com/openai/whisper), [SpeakerKit weights](https://huggingface.co/argmaxinc/speakerkit-coreml), [Parakeet](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3).

Предлагается manifest моделей: engine/version, model/revision, download size, checksum, languages, license/source, runtime requirements. Веса скачивать отдельными пакетами или включать в явно обозначенную full-сборку; поддержать прогресс, отмену, возобновление и offline-запуск после установки. В репозиторий не включать реальные встречи, токены и персональные логи. Публичные аудиофикстуры должны иметь разрешение на распространение.

## Следующий эксперимент и критерии выбора

Подготовить небольшой закрытый корпус с согласованным использованием: RU, EN и RU↔EN; чистый звук и ноутбук с эхом; 2 и 4–6 голосов; паузы, перебивания, числа, имена и рабочие термины. Включить записи 20, 60 и 90 минут. Вручную разметить хотя бы 5–10 минут каждой категории; один набор использовать для настройки, отдельный — для итоговой оценки.

Сравнивать последовательно:

1. Текущий WhisperKit 0.9.4 + turbo: точка отсчёта.
2. Новый закреплённый Argmax OSS + turbo: эффект обновления runtime.
3. На том же новом runtime large-v3 против turbo: эффект модели.
4. FluidAudio v3 и Ultra: альтернативный ASR, одинаковый вход.
5. SpeakerKit и FluidAudio offline на одном аудио; pyannote как лабораторный baseline.
6. Qwen3-ASR только при доступном воспроизводимом Mac runtime.

Измерять WER/CER отдельно RU/EN/mixed с опубликованной нормализацией, пропуски речи и выдуманный текст на тишине, точность чисел/имён, DER с указанными collar/overlap и ошибку числа говорящих. Для общей задачи нужен также speaker-attributed WER/cpWER: хороший текст с неверным автором остаётся ошибкой.

Для времени: холодный старт с компиляцией, тёплый повтор, полное время после Stop до транскрипта с голосами, отдельно время до заметок, пиковая RAM/swap. Не сравнивать raw decoder одной библиотеки с полным пайплайном другой. Зафиксировать питание, ОС, параметры, ревизии моделей; повторить короткий speed-тест несколько раз.

Предлагаемый продуктовый ориентир: 90-минутная встреча до транскрипта с голосами за 5 минут на M4 Pro при тёплых моделях. Это цель, не измеренный результат. Переход на новый default допустим после сравнения на отложенных встречах без ухудшения важных чисел/терминов и с устойчивой обработкой всей записи, восстановлением после отмены и проверенной offline-поставкой.

**Итог исследования:** текущая связка остаётся разумной базой; открытый SpeakerKit — первый кандидат для голосов, Parakeet через FluidAudio — первый кандидат для ускорения. Окончательный выбор требует локального сравнения на реальных RU/EN-встречах.
